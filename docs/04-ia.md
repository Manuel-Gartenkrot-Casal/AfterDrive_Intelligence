# 04 · IA: dónde se usa y cómo

## Dónde se usa

| Paso | Tipo | Si el proveedor falla |
|---|---|---|
| Decidir si una noticia es del rubro | LLM (temperatura 0,1) | Queda **pendiente**: no se guarda ni se descarta y se reintenta en la próxima corrida. Si responde algo que no es JSON, rechaza |
| Ficha de una noticia aprobada | LLM, tarea `clasificacion` | La noticia queda sin ficha y se usa su cuerpo |
| Plan de la nota | LLM, tarea `planificacion`, 4000 tokens | La nota se escribe sin plan |
| Corregir los problemas de una nota | LLM, tarea `correccion` | Queda la primera versión |
| Vectorizar noticias, notas y consultas | Embeddings | Se guarda sin `embedding`; se completa después con `python -m afterdrive.ingesta.embeddings` |
| Redactar la nota | LLM (streaming) | Se informa el error y no se guarda nada |
| Evaluar la nota (checklist de 9 puntos) | LLM (temperatura 0,1) | La nota se guarda igual, con `evaluacion: null` y sin reescribir |
| Verificar datos que no aparecen literal en las noticias | LLM, tarea `evaluacion` (una llamada, solo si hace falta) | Las cifras no encontradas cuentan como sin respaldo; los nombres, como dudosos |
| Resumir una edición en reglas | LLM, tarea `evaluacion` (como mucho 3 por nota) | Se reintenta en la próxima nota |
| Imagen destacada | Fotos de las noticias usadas. Con la API paga, el modelo de clasificación las **mira** (`llm.completar(..., imagenes=...)`) y elige la más apta; sin API paga va la primera | Va la primera foto |
| Traducir la nota a los otros idiomas del blog | LLM, tarea `traduccion` (vacía: el modelo de evaluación), al subirla a HubSpot | Esa versión no se sube; el error se ve al abrir la nota y "Volver a subir las traducciones" reintenta |
| Sugerir medios del sector (Buscar recomendaciones) | LLM, tarea `clasificacion`; cada sitio se verifica entrando a él | Se usan solo los buscadores |
| Estilo y SEO de la nota, enlaces inventados | **No es IA**: reglas en `generacion/calidad.py` y `generacion/verificacion.py` | — |
| Región de un texto | **No es IA**: palabras clave | — |

## Imágenes

`llm.completar(..., imagenes=[(bytes, mime)])` manda fotos junto al pedido: en Converse (Bedrock) como bloques `image` con los bytes en base64, en Chat Completions como `image_url` con una data URL; siempre antes del texto (Kimi K3 responde mejor así). Solo con la API paga en uso (`llm.ve_imagenes()`; `IMAGENES_CON_IA=0` lo apaga): los modelos configurados en Bedrock (GPT-6 Luna, GPT-5.6 Luna y Kimi K3) aceptan imágenes JPEG, PNG, WebP y GIF de hasta 3,75 MB. Con imágenes la llamada va sin streaming.

## Un solo módulo habla con los proveedores

`afterdrive/ia/llm.py` es **el único lugar** que llama a un proveedor. Todos usan la API estilo OpenAI (`/chat/completions`, `/embeddings`).

```python
from afterdrive.ia import llm

texto = llm.completar(system="...", user="...", temperature=0.3)
vectores = llm.embeber(["texto 1", "texto 2"])
```

Cada proveedor es un **Perfil** (URL, modelo, modelo de respaldo, ajustes de redacción). Para cambiar algo de un proveedor se toca su perfil, no se agregan `if` en otros archivos.

## Proveedores

| `AI_PROVIDER` | Dónde corre | Modelo principal | Notas |
|---|---|---|---|
| `openrouter` (**producción**) | Cloud | `mistralai/mistral-small-3.1-24b-instruct:free` | **No tiene embeddings** |
| `nvidia` | Cloud | `moonshotai/kimi-k3` (respaldo `openai/gpt-oss-20b`) | Modelos que "razonan": 16000 tokens y una instrucción extra para que no escriban su razonamiento |
| `local` | LM Studio en tu máquina (puerto 1234) | `mistral-7b-instruct-v0.3` | Prompt compacto: los modelos chicos pierden instrucciones largas |
| `paga` | Cloud, cualquier API compatible con OpenAI | Sin default: `PAGA_MODEL` | Solo por entorno (`PAGA_API_KEY`, `PAGA_BASE_URL`, `PAGA_MODEL`); a medio configurar cae a `local`. 16000 tokens de redacción |

### API paga (`AI_PROVIDER=paga`)

- **Bedrock (AWS)**: `PAGA_API=converse`. Usa la API Converse (`POST {PAGA_BASE_URL}/model/{ARN}/converse`) porque los application inference profiles no andan con Chat Completions. Sin streaming (la respuesta llega entera, `CONVERSE_TIMEOUT`) y sin `temperature` (los Luna rechazan el campo). Lee solo los bloques de texto: el razonamiento se descarta, pero se cobra como salida.
- **Tokens por llamada**: toda llamada a la IA, de cualquier proveedor, guarda en `consumo_ia` los tokens de entrada y salida, el límite de salida (`max_tokens`) y si la respuesta se cortó por ese límite (`truncado`), e imprime una línea `[TOKENS]` en la consola y en el log de la corrida. Con streaming se pide el uso real (`stream_options`, salvo LM Studio local); si el proveedor no lo informa se estima. El tablero de la vista Desarrollador lo muestra por día, por tarea y llamada por llamada (`GET /api/metricas`).
- **Consumo y tope**: solo las llamadas de la API paga tienen costo; las demás se guardan con `costo_usd` 0 y no cuentan para el tope. Cada llamada paga guarda tokens y costo en `consumo_ia` (Mongo). El costo sale del precio del **modelo que contestó** (USD por 1M de tokens, entrada/salida): el de `PAGA_MODEL_<TAREA>` cobra `PAGA_PRECIO_<TAREA>`, el de `PAGA_FALLBACK_MODEL` cobra `PAGA_PRECIO_FALLBACK`, el de `PAGA_MODEL` cobra `PAGA_PRECIO_GENERAL`; un modelo sin precio conocido se cobra al más alto. Sin tokens informados (timeout, stream cortado) se registra una estimación por lo alto. Si el mes llega a `PAGA_TOPE_MENSUAL_USD` (40 por defecto) o no se puede leer el registro, el chat pasa a NVIDIA y la clasificación vuelve a Jev hasta el mes siguiente. El dashboard lo avisa.

- **Un modelo por tarea**: `PAGA_MODEL_CLASIFICACION`, `PAGA_MODEL_EVALUACION`, `PAGA_MODEL_REDACCION` y, opcionales, `PAGA_MODEL_PLANIFICACION` y `PAGA_MODEL_CORRECCION`. El plan y la corrección, sin variable propia, usan el modelo de **evaluación** (`llm.RESPALDO_TAREA`): son textos cortos o retoques y no necesitan el modelo caro. El resto, sin variable, usa `PAGA_MODEL`.
- **Costo por nota**: `consumo.medir()` suma lo que se gasta durante una generación; queda en la nota (`costo`) y en el log de la corrida (`[COSTO] Esta nota: USD …`).
- **Clasificación**: con la API paga en uso clasifica ella y Jev no se consulta. Si la API paga está en pausa por el tope, vuelve la cadena normal (Jev primero).
- **Payload**: manda `max_completion_tokens` (lo que pide OpenAI); `PAGA_CAMPO_MAX_TOKENS=max_tokens` para otro proveedor. `PAGA_TEMPERATURA=0` deja de mandar `temperature` si el modelo la rechaza.
- **Modo API paga (vista Cliente)**: un interruptor en la barra lateral, visible en las dos vistas, pone **todo el pipeline** en la API paga por **24 horas como máximo**: la Corrida programada del día más las notas y scrapings que se pidan a mano en ese tiempo. Pide confirmación al prenderlo (con el gasto del mes) y se apaga solo al vencer, volviendo al proveedor elegido en Desarrollador, que no se pisa. Prenderlo otra vez no extiende el plazo. No se puede prender sin la API paga configurada ni con el tope mensual alcanzado; si el tope se alcanza con el modo prendido, el chat pasa a NVIDIA como siempre. Elegir otro proveedor a mano en Desarrollador lo apaga. El vencimiento vive en `MODO_PAGO_HASTA` (lo heredan los subprocesos y el corte es exacto aunque haya una Corrida a mitad) y en Mongo (`config`, clave `modo_pago`), de donde lo retoman el servidor al reiniciar y las Corridas de GitHub Actions. Código: `afterdrive/ia/modo_pago.py`.
- **Embeddings**: solo con `EMBEDDINGS_PROVIDER=paga` + `PAGA_EMB_MODEL`. Elegir "API paga" en el dashboard no cambia los embeddings.
- **Cada vector guarda `embedding_modelo`** (`proveedor/modelo`). El RAG no compara vectores de modelos distintos. Al cambiar de modelo: `python -m afterdrive.ingesta.embeddings` (re-vectoriza lo de otro modelo; los vectores viejos sin etiqueta y del largo actual solo se etiquetan) y rehacer el índice de Atlas con las dimensiones nuevas (ver [08-despliegue.md](08-despliegue.md)).

- **Los embeddings van por otro proveedor**: `EMBEDDINGS_PROVIDER=nvidia` (modelo `nvidia/nemotron-3-embed-1b`), porque OpenRouter no tiene.
- El proveedor se cambia desde el dashboard (vista Desarrollador, pie de la barra lateral) y queda guardado en Mongo.
- No se puede elegir `local` si LM Studio no responde.
- `llm.disponible()` cachea si el proveedor responde: 10 minutos si respondió, 1 minuto si no.

## Errores comunes

| Error | Qué hace `llm.py` | Qué hacés vos |
|---|---|---|
| 429 (límite de uso) | Prueba el modelo de respaldo y reintenta con espera creciente | Esperar o cambiar de modelo |
| 404/410 (modelo dado de baja) | Prueba el respaldo; si falla, muestra los modelos disponibles hoy | Cambiar `OPENROUTER_MODEL` / `NVIDIA_MODEL` |
| Sin respuesta en 180 s | Corta (`STREAM_READ_TIMEOUT`) | Reintentar |
| El modelo gastó los tokens razonando | Reintenta con el respaldo | — |

> Los modelos gratuitos cambian seguido. Si la generación empieza a fallar con 404/410, casi siempre es eso.

## Prompts

| Qué | Dónde |
|---|---|
| Clasificador de noticias y checklist de calidad | `ia/lm_studio.py` (el nombre es histórico; sirve para todos los proveedores) |
| Redacción de notas | `ia/redaccion.py`: piezas comunes + bloque de la persona + voz de la región |
| Parámetros del pedido (región, categorías, clientes) | `generacion/generar_nota_fase2.py` |

**Regla de oro de los prompts de redacción: no inventar cifras, empresas ni casos.** Los hechos salen solo de las noticias de contexto.

## Personas

| Persona | Enfoque |
|---|---|
| `comercial` (por defecto) | Vende una solución concreta al problema del lector |
| `analitico` | Explica un fenómeno técnico o de negocio a partir de las noticias |
| `periodistico` | Cuenta una novedad con pirámide invertida |
| `divulgativo` | Explica didácticamente un solo concepto |
| `ejecutivo` | Visión de alto nivel para quienes deciden |

## Revisión que reescribe

Cada versión de la nota se revisa con: datos contra las noticias (`generacion/verificacion.py`), estilo y SEO sin IA (`generacion/calidad.py`), el checklist del LLM (`ia/lm_studio.py`), el parecido con las últimas notas y el umbral calibrado (`calibracion.py`). Un problema **grave** (datos sin respaldo; un lineamiento crítico del checklist: `sin_alucinaciones`, `sin_paywall`, `no_repetitivo`, `estructura_correcta`; falta título, meta o la sección de implicancias; huecos sin dato; tres o más muletillas; nota repetida; puntaje bajo el umbral) hace escribirla una vez más con la lista de problemas. Queda la que tiene menos problemas graves y, a igualdad, más lineamientos. Todo se guarda con la nota y se ve al revisarla en el dashboard. El recorrido completo está en [03 Pipelines](03-pipelines.md).

Costo extra por nota respecto de antes: el plan (una llamada barata), la verificación (una llamada barata, solo si algún dato no aparece literal) y, la primera vez, las fichas de las noticias elegidas que no la tengan (llamadas baratas). Lo demás es sin IA. La segunda versión ya no es una redacción entera sino una corrección con el modelo barato, salvo que la nota repita a una reciente.

## Saneo

`ia/saneo.py` convierte la respuesta cruda en una Nota publicable o la rechaza con un motivo: quita envoltorios JSON y fences de markdown, corta texto degenerado, elimina oraciones y secciones repetidas, y **descarta la respuesta si el modelo escribió su plan o razonamiento** en lugar de la nota. Tiene sus propios tests (`tests/test_saneo.py`): si cambiás algo, agregá el caso que lo motivó.

## Jev (TypeSafe)

`ingesta/jev_clasificador.py` permite usar Jev como primer clasificador. **Hoy no se usa**: sin `TYPESAFE_API_KEY` se saltea y clasifica el LLM.
